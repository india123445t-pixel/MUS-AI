## Independent comparability findings

### A. TEMPLATE / EVALUATOR FAMILY OVERLAP
Historical train, dev, and shadow are generated by the same W02 `_core` / `_task` / `_render_prompt` machinery and the same 14 atomic one-operation DSL families.

The index sets are disjoint:
- dev: 0..1
- shadow: 2..3
- training: 4..19

This prevents literal index reuse, but the evaluation remains structurally close to training. Therefore the result is best interpreted as in-family held-out gain rather than strong compositional generalization.

### B. BASELINE / FINAL SAMPLING IS NOT PAIRWISE
Historical `eval_tasks()` derives generation seed from `label + ":" + task_id`.

Baseline labels differ from final labels, so baseline and final use different random sampling streams on the same task. This creates a lucky-sampling/comparability risk.

Agent 03 independently corroborated this finding.

### C. CHECKPOINT CURVE ALSO HAS A SEED CONFOUND
Each `dev_after_<step>` label changes the seed. Dev also participates in early-stop logic.

The historical run reached the full 672-update cap and did not select an earlier checkpoint, so there is no evidence that R0 cherry-picked an earlier checkpoint after seeing a better dev score. The limitation is stochastic comparability and dev reuse, not proven post-hoc checkpoint selection.

### D. SINGLE-SAMPLE UNCERTAINTY
Historical evaluation used one sampled answer per task with temperature 0.7, top-p 0.8, top-k 20. It did not estimate repeated-seed variance or a paired confidence/sign test.

### E. ARTIFACT CUSTODY BOUNDARY
Run `36307917194` has zero uploaded GitHub Actions artifacts. Agent 01 independently established that the controller downloaded `evidence.tgz` only to ephemeral runner storage and deleted the pod before durable preservation.

The durable receipt proves the expected adapter hash and save/reload result, but the original R0 adapter bytes are not currently proven recoverable for independent byte-level re-hash/inference.
